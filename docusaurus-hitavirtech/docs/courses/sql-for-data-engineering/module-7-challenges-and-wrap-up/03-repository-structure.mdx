<LearningObjectives>

- Organize your course artifacts into a clean, portfolio-ready repository
- Map each course module to its directory of runnable SQL files

</LearningObjectives>

If you saved your SQL as you worked through the course, arrange it like this —
the layout doubles as a portfolio piece you can push to GitHub and link from
your resume:

```

├── README.md
├── 01_setup/
│   ├── 01_create_schema.sql
│   ├── 02_create_tables.sql
│   ├── 03_seed_customers.sql
│   ├── 04_seed_products.sql
│   ├── 05_seed_orders.sql
│   └── 06_seed_order_items.sql
├── 02_examples/
│   ├── 03_select_where.sql
│   ├── 04_create_table.sql
│   ├── 05_insert_update_delete.sql
│   ├── 06_conditional.sql
│   ├── 07_aggregations.sql
```

**Happy querying — and remember: bring the data.**

<KeyTakeaways>

- Keep setup, examples, capstone, integrations, and challenges in separate numbered directories
- The `01_setup/` scripts make the whole repository reproducible from a blank MySQL install
- Docs (`er_diagram.md`, `style_guide.md`) live in the repo and evolve with the schema
- A clean course repository doubles as an interview portfolio piece

</KeyTakeaways>
