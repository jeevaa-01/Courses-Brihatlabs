# Integration with Airflow

*⏱ Estimated time: 45 minutes*

:::note[🎯 Learning objectives]

By the end of this section, you will be able to:

- Orchestrate the pipeline with an Airflow DAG.
- Keep orchestration logic separate from transformation logic.

:::

Airflow can orchestrate Spark jobs.

Simplified example:

```python
from datetime import datetime

from airflow import DAG
from airflow.operators.bash import BashOperator

with DAG(
    dag_id="hitavir_pyspark_sales_pipeline",
    start_date=datetime(2026, 1, 1),
    schedule="@daily",
    catchup=False,
) as dag:
    run_pipeline = BashOperator(
        task_id="run_pyspark_pipeline",
        bash_command=(
            "cd /path/to/project && "
            "python -m src.pipeline"
        ),
    )
```

For clusters, Airflow may use:

- SparkSubmitOperator.
- Databricks operators.
- KubernetesPodOperator.
- Cloud-specific operators.

:::info[📌 Key takeaways]

- Airflow schedules and monitors; Spark transforms.
- Use operators (SparkSubmit, Databricks) to launch heavy work outside the scheduler.
- Separated concerns keep both systems simple to operate.

:::

:::tip[💡 HitaVir Tech Tip]

Do not use Airflow to perform heavy data processing inside the scheduler process.

:::

:::info[🚀 Pro Tip]

Keep orchestration logic separate from transformation logic.

:::
