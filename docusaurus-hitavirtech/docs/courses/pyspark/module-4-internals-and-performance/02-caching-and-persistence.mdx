# Caching and Persistence

*⏱ Estimated time: 55 minutes*

:::note[🎯 Learning objectives]

By the end of this section, you will be able to:

- Cache and persist DataFrames correctly and release them with `unpersist()`.
- Choose an appropriate storage level.
- Decide when caching helps and when it hurts.

:::

### Cache a DataFrame

```python
valid_df.cache()
```

Trigger materialization:

```python
valid_df.count()
```

Reuse:

```python
valid_df.groupBy("region").count().show()
valid_df.groupBy("product").count().show()
```

### Unpersist

```python
valid_df.unpersist()
```

### Persistence levels

```python
from pyspark import StorageLevel

valid_df.persist(
    StorageLevel.MEMORY_AND_DISK
)
```

### When to cache

Cache when:

- The same expensive DataFrame is reused.
- Interactive analysis repeats actions.
- Iterative algorithms reuse data.

Do not cache when:

- DataFrame is used once.
- Dataset is too large.
- Recalculation is cheap.
- Memory pressure is high.

### ✅ Checkpoint

Cache a DataFrame, run two aggregations, and unpersist it.

:::info[📌 Key takeaways]

- Caching is lazy — an action materializes it.
- Cache only expensive, reused DataFrames, and always `unpersist()` afterward.
- Wrong caching hurts performance through memory pressure.

:::

:::tip[💡 HitaVir Tech Tip]

Always unpersist DataFrames when they are no longer needed.

:::

:::info[🚀 Pro Tip]

Caching the wrong DataFrame can reduce performance by increasing memory pressure and garbage collection.

:::
