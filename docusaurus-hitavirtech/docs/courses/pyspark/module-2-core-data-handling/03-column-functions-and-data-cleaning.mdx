# Column Functions and Data Cleaning

*⏱ Estimated time: 90 minutes*

:::note[🎯 Learning objectives]

By the end of this section, you will be able to:

- Standardize text, parse dates safely with `try_to_date()`, and cast types.
- Handle nulls, duplicates, and invalid categories with built-in functions.
- Split valid and rejected records null-safely, preserving rejection reasons.

:::

### Clean text

```python
cleaned_df = (
    sales_df
    .withColumn(
        "region",
        F.upper(F.trim(F.col("region")))
    )
    .withColumn(
        "product",
        F.initcap(F.trim(F.col("product")))
    )
)
```

### Parse dates

```python
cleaned_df = cleaned_df.withColumn(
    "transaction_date",
    F.try_to_date(
        F.col("transaction_date"),
        "yyyy-MM-dd"
    )
)
```

:::warning[ANSI mode]

Spark 4 and current Databricks runtimes (including serverless) enable ANSI SQL mode by default. Under ANSI mode, `to_date()` raises `CANNOT_PARSE_TIMESTAMP` on malformed input instead of returning null. Use `try_to_date()` (and `try_cast()` for risky casts) when you want invalid values to become null so your validation rules can catch them.

:::

### Cast values

```python
cleaned_df = cleaned_df.withColumn(
    "quantity",
    F.col("quantity").cast("integer")
)
```

### Handle nulls

Fill:

```python
cleaned_df = cleaned_df.fillna(
    {
        "quantity": 0,
        "region": "UNKNOWN"
    }
)
```

Drop rows with nulls:

```python
cleaned_df = cleaned_df.dropna(
    subset=["transaction_id", "transaction_date"]
)
```

### Conditional logic

```python
cleaned_df = cleaned_df.withColumn(
    "revenue_band",
    F.when(
        F.col("revenue") >= 100000,
        F.lit("VERY_HIGH")
    )
    .when(
        F.col("revenue") >= 50000,
        F.lit("HIGH")
    )
    .otherwise(F.lit("STANDARD"))
)
```

### Replace values

```python
cleaned_df = cleaned_df.replace(
    {
        "S": "SOUTH",
        "N": "NORTH",
        "E": "EAST",
        "W": "WEST"
    },
    subset=["region"]
)
```

### Remove duplicates

```python
cleaned_df = cleaned_df.dropDuplicates(
    ["transaction_id"]
)
```

### String functions

```python
cleaned_df.select(
    F.length("product").alias("product_length"),
    F.substring("transaction_id", 1, 1).alias("prefix"),
    F.concat_ws(
        "-",
        "region",
        "product"
    ).alias("region_product")
).show()
```

### Date functions

```python
cleaned_df = (
    cleaned_df
    .withColumn(
        "transaction_year",
        F.year("transaction_date")
    )
    .withColumn(
        "transaction_month",
        F.month("transaction_date")
    )
    .withColumn(
        "transaction_day",
        F.dayofmonth("transaction_date")
    )
)
```

### Validate categories

```python
allowed_regions = ["NORTH", "SOUTH", "EAST", "WEST"]

valid_df = cleaned_df.filter(
    F.col("region").isin(allowed_regions)
)
```

### Separate valid and rejected records

```python
valid_condition = (
    F.col("transaction_id").isNotNull()
    & F.col("transaction_date").isNotNull()
    & F.col("region").isin(allowed_regions)
    & (F.col("quantity") > 0)
    & F.col("unit_price").isNotNull()
    & (F.col("unit_price") >= 0)
)

is_valid = F.coalesce(valid_condition, F.lit(False))

valid_df = cleaned_df.filter(is_valid)
rejected_df = cleaned_df.filter(~is_valid)
```

:::danger[Null logic warning]

SQL uses three-valued logic. When `quantity` is null, `quantity > 0` evaluates to null, and `~null` is also null — so filtering on `~valid_condition` directly would silently drop null-containing rows from **both** DataFrames. Wrapping the condition in `F.coalesce(..., F.lit(False))` turns unknown into false, so every row lands in exactly one of the two outputs. Verify with `valid_df.count() + rejected_df.count() == cleaned_df.count()`.

:::

:::info[📌 Key takeaways]

- `try_to_date()` and `try_cast()` turn invalid values into nulls your validation rules can catch.
- SQL three-valued logic makes negated null conditions silently drop rows — coalesce to false.
- Preserve rejected records with explicit rejection reasons instead of discarding them.

:::
