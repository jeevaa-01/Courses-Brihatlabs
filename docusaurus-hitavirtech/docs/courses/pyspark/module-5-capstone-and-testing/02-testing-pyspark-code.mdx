# Testing PySpark Code

*⏱ Estimated time: 65 minutes*

:::note[🎯 Learning objectives]

By the end of this section, you will be able to:

- Write pytest fixtures and unit tests for PySpark transformations.
- Compare result rows and schemas against expected values.
- Design tests around representative edge cases, not only happy paths.

:::

### Why test transformations?

Tests protect against:

- Incorrect business logic.
- Schema changes.
- Null handling defects.
- Duplicate handling defects.
- Join multiplication.
- Invalid date logic.
- Refactoring errors.

### Test small DataFrames

Use small in-memory datasets.

```python
def test_revenue_calculation(spark):
    input_df = spark.createDataFrame(
        [("T001", 2, 500.0)],
        ["transaction_id", "quantity", "unit_price"]
    )

    result_df = input_df.withColumn(
        "revenue",
        F.col("quantity") * F.col("unit_price")
    )

    result = result_df.collect()[0]

    assert result.revenue == 1000.0
```

### Compare rows

```python
actual = result_df.orderBy("transaction_id").collect()
expected = expected_df.orderBy("transaction_id").collect()

assert actual == expected
```

### Compare schemas

```python
assert result_df.schema == expected_df.schema
```

### Test invalid inputs

Test:

- Null IDs.
- Invalid regions.
- Negative quantity.
- Missing price.
- Duplicate IDs.
- Invalid dates.

### ✅ Checkpoint

Run all tests:

```powershell
pytest -q
```

- Test pure transformation functions independently from file I/O.
- Assert on both data and schema.
- Edge cases (nulls, duplicates, invalid values) catch more defects than happy paths.
