Two legendary approaches to data warehouse architecture.

### Kimball (Bottom-Up)

**Ralph Kimball's approach:** Build dimensional data marts first, then integrate them into an enterprise warehouse.

![Kimball vs Inmon](/img/courses/diagrams/kimball-vs-inmon.svg)

**Key principles (Inmon, top-down):**

- Single source of truth first
- Normalized (3NF) enterprise model
- Data marts derived from the warehouse
- More upfront design work

### Comparison

![Kimball vs Inmon Table](/img/courses/diagrams/kimball-inmon-table.svg)

:::tip[HitaVir Tech says]
"In the real world, most modern companies use a hybrid approach — Kimball-style star schemas for analytics, with Inmon-level governance. Know both, but start with Kimball for practical projects."
:::

<KeyTakeaways>

- **Kimball** (bottom-up): star-schema data marts first, integrated later — faster delivery, agile-friendly
- **Inmon** (top-down): normalized 3NF enterprise warehouse first, marts derived from it — heavier governance
- Kimball delivers value in weeks; Inmon takes months but suits large regulated enterprises
- Most modern companies run a hybrid: Kimball-style stars with Inmon-level governance

</KeyTakeaways>
