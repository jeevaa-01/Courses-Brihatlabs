# Data Modelling for Data Engineering — Beginner to Advanced

**Instructor:** HitaVir Tech · **Level:** Beginner to Advanced · **Estimated total:** ~3 hours · **5 modules · 16 lessons**

Welcome to **Data Modelling for Data Engineering** by **HitaVirTech**! This is
the most comprehensive data modelling course in the program — built for
aspiring and working Data Engineers. We go from absolute basics to enterprise
architect-level concepts with real SQL, PySpark, and cloud platform examples.

**Data modelling** is the process of designing how data is organized, stored,
and related in a database system. It is the **blueprint** of your data
platform — just like an architect draws building plans before construction
begins. You would never start laying bricks without a plan; data modelling is
that plan for your data — it defines the rooms (tables), doors
(relationships), and layout (schema) before any data flows in.

<LearningObjectives>

- Design conceptual, logical, and physical data models and know when each applies
- Build and query star schemas with fact tables, dimensions, and SCD Type 2 history
- Compare Kimball, Inmon, Data Vault, and medallion (lakehouse) architectures
- Tune cloud warehouse models with partitioning, clustering, and Z-ORDER
- Answer the data modelling questions asked in real Data Engineering interviews

</LearningObjectives>

## Why data modelling matters

![Good vs Bad Modelling](/img/courses/diagrams/good-vs-bad-modelling.svg)

Good modelling delivers **performance** (queries run 10-100x faster),
**consistency** (everyone gets the same numbers), **scalability**,
**maintainability**, **cost optimization**, and built-in **compliance**. Poor
modelling produces reports that disagree, 15-table JOINs for simple questions,
8-hour ETL jobs, and cloud bills that double every quarter.
