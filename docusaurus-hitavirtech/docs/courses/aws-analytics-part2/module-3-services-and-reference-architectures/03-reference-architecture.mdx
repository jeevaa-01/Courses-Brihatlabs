### Reference 1 — Batch BI on a Lake House

![S3](/img/courses/aws-icons/s3.png) ![Glue](/img/courses/aws-icons/glue.png) ![Redshift](/img/courses/aws-icons/redshift.png) ![QuickSight](/img/courses/aws-icons/quicksight.png)

```
  Operational DBs (RDS, Aurora)      SaaS apps (Salesforce)
           |                                |
           +---- AWS DMS (CDC) ----+  AppFlow
                                   |
                                   v
            +--------------------------------------+
            |     Amazon S3 Data Lake              |
            |     raw -> curated (Parquet)         |
            +---------------+----------------------+
                            |
                            v  (Glue ETL, Data Quality, Catalog)
                            |
            +---------------+----------------------+
            |   Amazon Redshift (curated tables)   |
            |   - Star schemas                     |
            |   - Nightly loads via COPY           |
            +---------------+----------------------+
                            |
                            v
                   Amazon QuickSight
                     (SPICE dashboards)
                            |
                            v
                        Executives
```

**When to pick it:** Finance, ops, exec reporting. Stable queries, predictable loads.

### Reference 6 — Data Mesh

![Lake Formation](/img/courses/aws-icons/lake-formation.png) ![DataZone](/img/courses/aws-icons/datazone.png) ![S3](/img/courses/aws-icons/s3.png)

```
  Domain A (Orders)      Domain B (Marketing)     Domain C (Finance)
  owns its own pipes     owns its own pipes       owns its own pipes
     |                       |                         |
     v                       v                         v
  S3 bucket + Glue        S3 bucket + Glue          S3 bucket + Glue
  Catalog (Orders)        Catalog (Marketing)       Catalog (Finance)
     |                       |                         |
     +-----------+-----------+-------------------------+
                 |
                 v
       +-----------------------------------+
       |   Lake Formation  (central RBAC)  |
       |   + Amazon DataZone  (discovery)  |
       +---------------+-------------------+
                       |
          +------------+------------+
          |            |            |
          v            v            v
        Analyst    Data sci.    Executive
       (Athena)   (SageMaker)   (QS / Q)
```

**When to pick it:** Large enterprises where domain teams must own their data products, but a central platform team guarantees governance.

### Reference Architecture Comparison

| # | Pattern | Primary V | Storage | Compute | Serve |
|:-:|---------|:-------:|---------|---------|-------|
| 1 | Batch BI | Volume | S3 + Redshift | Glue, Redshift | QuickSight |
| 2 | Real-Time | Velocity | Kinesis + S3 | Kinesis Analytics, Lambda | OpenSearch, QuickSight |
| 3 | Log Obs. | Velocity + Variety | OpenSearch + S3 | Firehose | Kibana, Athena |
| 4 | 360 | Variety + Value | S3 + Redshift | Glue | QuickSight + apps |
| 5 | ML | Value | S3 | Glue, SageMaker | Endpoint in app |
| 6 | Mesh | Veracity + Value | Distributed S3 | Per-domain | Lake Formation + DataZone |

:::tip[HitaVir Tech says]
"Architects don't memorize 50 services — they memorize 6 shapes. When someone brings a new problem, they map it to a shape first, then pick services to fit. Copy these six patterns. Most of your career, you'll be adapting one of them."
:::

<KeyTakeaways>

- Each of the six use cases has a whiteboard-ready reference architecture you can copy and adapt
- Batch BI flows sources → S3 lake → Redshift star schemas → QuickSight dashboards
- Real-Time fans a Kinesis stream out to continuous SQL, Lambda alerting, and Firehose-to-S3 history
- Log Observability splits hot search (OpenSearch, ~30 days) from cold archive (S3 + Athena, years)
- Data Mesh gives each domain its own S3 + Glue stack under central Lake Formation + DataZone governance

</KeyTakeaways>
