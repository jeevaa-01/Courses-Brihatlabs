### S3 Data Lake — Medallion Architecture

```
  s3://hitavirtech-analytics/
    |
    +-- raw/             <-- Bronze:  untouched source data
    |     +-- sales/2026/04/22/orders.csv
    |     +-- inventory/2026/04/22/stock.json
    |
    +-- curated/         <-- Silver:  cleaned, typed Parquet
    |     +-- sales_fact/year=2026/month=04/day=22/part-001.parquet
    |
    +-- analytics/       <-- Gold:    pre-aggregated for BI
          +-- daily_revenue/year=2026/month=04/day=22/part-001.parquet
```

- 🥉 **Raw (bronze)** — the data lake's truth. Reprocess from here if anything goes wrong.
- 🥈 **Curated (silver)** — cleaned, typed. Parquet for fast analytics.
- 🥇 **Analytics (gold)** — pre-aggregated. Powers dashboards.

### Volume Decision Tree

```
                      How much data?
                            |
       +--------------------+--------------------+
       |                    |                    |
     < 1 TB              1-100 TB             > 100 TB
       |                    |                    |
       v                    v                    v
    RDS or                S3 +               S3 + EMR +
  Redshift Serverless    Athena              Redshift +
  (small + cheap)       (most common)        Lake Formation
                                             (huge platform)
```

:::tip[HitaVir Tech says]
"Start with S3. Every analytics service on AWS reads from it. You'll never regret putting data into S3 — you may regret putting it anywhere else first."
:::

<KeyTakeaways>

- S3 is the data-lake foundation: 11 nines of durability, practically unlimited scale, read by every analytics service
- S3 storage classes trade access speed for cost — Standard (hot) down to Glacier Deep Archive (compliance vault)
- The medallion layout (raw/bronze → curated/silver → analytics/gold) organizes the lake by refinement stage
- Match the stack to scale: RDS/Redshift Serverless under 1 TB, S3 + Athena for 1-100 TB, add EMR + Redshift + Lake Formation beyond

</KeyTakeaways>
